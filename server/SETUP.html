決済接続手順（運営者向け・非公開）

現在の本番設定は BILLING_ENABLED=false。既存の編集機能は無料のままで、決済・ログイン・通知受信は利用できません。コードはテスト環境のみ有効化可能です。本番の課金開始には別途検証と切り替えが必要です。

1. 利用者の認証サービス

OpenID Connectの認可コードフロー、PKCE S256、署名付きIDトークン（RS256またはES256）に対応するサービスを接続します。アプリ側でパスワードは保存しません。設定は実際のサービスを選定・登録した後に取得してください。

  • OIDC_ISSUER：Discovery文書のissuerと完全一致する値
  • OIDC_CLIENT_ID：登録したアプリのクライアントID
  • OIDC_CLIENT_SECRET：必要な場合のみ。client_secret_postを利用できるアプリ設定が必要
  • 許可するコールバック：テスト用APP_ORIGIN + /api/auth/callback
  • スコープ：openid。メール・動画・選手情報は認証データベースへ保存しません。

2. テスト用のCloudflare構成

wrangler.billing.example.jsoncを非公開のテスト用設定として複製し、専用のD1データベースとテストホストを設定します。schema.sqlをそのテスト用データベースに適用します。設定例のREPLACE_WITHを残したまま有効化しないでください。本番アプリのデータベース・元動画には触れません。

秘密情報はCloudflareの暗号化されたSecretsまたはSecrets Storeへ設定し、ソースコード・公開ファイル・チャットに記載しないでください。

設定名用途
STRIPE_SECRET_KEYFootball Analyzer テスト専用の制限付きAPIキーを推奨。Customer作成・取得、Checkout Session作成・取得、Subscription/Price/Chargeの読取、Portal Session作成に必要な権限のみ。
STRIPE_WEBHOOK_SECRETテスト用Webhookエンドポイントの署名シークレット。
OIDC_CLIENT_SECRET認証サービスが必要とする場合のみ。

通知先：テスト用APP_ORIGIN + /api/stripe/webhook。APIバージョン2026-09-30.endiveを前提とした実装です。登録後に実際のAPIレスポンス形状も確認してください。

通知は生の本文とタイムスタンプ付き署名を確認し、イベントIDで重複を除外します。契約状態はStripeの最新状態を照会するため、古い通知を受けても有料状態を再付与しません。返金・異議申立・不正検知では該当顧客を確認待ちとし、運営者が確認するまで自動解除しません。解除のための一般公開APIはありません。

4. 検証してから有効化

テスト用の設定がそろった後、BILLING_ENABLED=trueにし、テストカードでログイン→500円の申込→有料状態確認→支払失敗→期間終了時の解約→返金を検証します。APIキーはtest環境のみ許可し、live環境では常に受付を停止します。

自動テスト：node --test server/billing.test.mjs。モックによる検証であり、実サービス間の接続テストの代わりではありません。
